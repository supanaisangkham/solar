# โซลาร์บ้านฉัน คุ้มไหม? — Web App V1

แอปภาษาไทย Mobile-first ธีมน้ำเงิน–ขาว–เหลือง ใช้ React + TypeScript + Vite คำนวณในเบราว์เซอร์ ไม่มี backend หรือบัญชีผู้ใช้ **ยังไม่ได้ deploy และยังไม่ยืนยันโครงการเงินสนับสนุนหรือสิทธิขายไฟ**

## เปิดใช้ในเครื่อง

ต้องมี Node.js 22.12+ หรือ 24 และ npm เปิด terminal ในโฟลเดอร์นี้:

```sh
npm ci
npm run dev
```

เปิด URL ที่แสดงใน terminal โดยปกติคือ http://127.0.0.1:5173/

```sh
npm test
npm run build
```

ไฟล์พร้อมเผยแพร่อยู่ใน `dist/` ต้องให้บริการผ่าน HTTP ไม่เปิด index.html โดยตรงด้วย file://

## ฟังก์ชัน

- คำนวณด่วนจากค่าไฟ หน่วยไฟ (ไม่กรอกใช้ 0) ราคาต่อหน่วยและสัดส่วนกลางวัน
- บันทึกมิเตอร์สะสมเช้า 08:00 เย็น 17:00 และเช้าถัดไป 1–7 วัน ตรวจข้อมูลไม่ครบ ตัวเลขลดลง และวันที่ซ้ำ
- เปรียบเทียบ On-Grid กับระบบแบตเตอรี่ ขนาดระบบ ผลผลิต สัดส่วนโหลดตรงเวลา ความจุและประสิทธิภาพแบตเตอรี่ปรับได้
- ราคาติดตั้ง เงินสนับสนุนที่ยืนยันแล้ว เงินจ่ายเอง เงินกู้แบบลดต้นลดดอก ค่างวด ดอกเบี้ยรวม ค่าดูแลและค่าเปลี่ยนแบตเตอรี่
- ภาระรายเดือน เงินลงทุนสุทธิ ต้นทุนสุทธิตลอดช่วงประเมิน และช่วงจำลองผลผลิต
- บันทึก localStorage อัตโนมัติ แจ้งเมื่อบันทึกไม่ได้ ดาวน์โหลด JSON และล้างข้อมูลโดยยืนยันก่อน

JSON ที่ดาวน์โหลดใช้เก็บสำรองและตรวจสอบค่า ยังไม่มีเมนูนำเข้าใน V1 ข้อมูลคนละเบราว์เซอร์/URL จะไม่ใช้ร่วมกัน อย่าฝากข้อมูลสำคัญไว้ใน localStorage เพียงแห่งเดียว

## สูตรและหน่วย

ใช้ 30 วันต่อเดือน; 1 หน่วย = 1 kWh

1. หน่วยรายเดือน = หน่วยจากบิล ถ้ามากกว่า 0 มิฉะนั้นค่าไฟ ÷ มูลค่าต่อหน่วย
2. โหลดกลางวัน = หน่วยรายเดือน × สัดส่วนกลางวัน; กลางคืน = ส่วนที่เหลือ
3. โหมดมิเตอร์: กลางวัน = เฉลี่ย(เย็น − เช้า) × 30, กลางคืน = เฉลี่ย(เช้าถัดไป − เย็น) × 30
4. ผลผลิต = kWp × ผลผลิตสุทธิต่อ kWp ต่อวัน × 30
5. ใช้ตรง = min(โหลดกลางวัน × สัดส่วนตรงเวลา, ผลผลิต)
6. ไฟจากแบตเตอรี่ = min(ไฟส่วนเกิน × ประสิทธิภาพ, ความจุใช้งาน × 30, โหลดกลางคืน)
7. ประหยัด = min(ค่าไฟเดิม, (ใช้ตรง + ไฟจากแบตเตอรี่) × มูลค่าไฟต่อหน่วย)
8. เงินลงทุนสุทธิ = ราคาติดตั้ง − min(เงินสนับสนุนที่ยืนยันแล้ว, ราคาติดตั้ง); เงินกู้ = เงินลงทุนสุทธิ − min(เงินจ่ายเอง, เงินลงทุนสุทธิ)
9. ค่างวด A = P × r / (1 − (1+r)^(-n)); r = ดอกเบี้ยต่อปี / 1200; n = ปี × 12; ดอกเบี้ย 0 ใช้ P/n
10. ภาระรายเดือนระหว่างกู้ = ค่าไฟเดิม − ประหยัด + ค่างวด + ค่าดูแล/12 หลังหมดกู้ให้ตัดค่างวดออก
11. คืนทุนอย่างง่าย = ลงทุนสุทธิ / (ประหยัดต่อปี − ค่าดูแล) ถ้าตัวหารไม่เป็นบวก แสดงไม่คืนทุน ไม่รวมดอกเบี้ยและการเปลี่ยนอุปกรณ์
12. ต้นทุนตลอดช่วงประเมิน = ค่าไฟคงเหลือตลอดช่วง + ค่าดูแล + เงินลงทุนสุทธิ + ดอกเบี้ยเต็มสัญญา + ค่าเปลี่ยนแบตเตอรี่หนึ่งครั้ง (เมื่อปีเปลี่ยนไม่เกินช่วงประเมิน)

ค่าตั้งต้นทั้งหมดเป็นตัวอย่างสำหรับทดลอง ไม่ใช่อัตราไฟ ข้อเสนอสินเชื่อ ราคาตลาด หรือประมาณการจากการสำรวจพื้นที่จริง ไม่มีรายได้ขายไฟ และเงินสนับสนุนเริ่มต้น 0 บาท แม้กรอก 50,000 บาทก็ไม่นับจนกว่าจะเลือกว่ายืนยันสิทธิแล้ว ผู้ใช้ต้องตรวจสอบหลักฐานกับหน่วยงานที่เกี่ยวข้องเอง

ช่วงความไม่แน่นอนเปลี่ยนเฉพาะผลผลิต ±เปอร์เซ็นต์ที่กำหนด ไม่ใช่ช่วงความเชื่อมั่นทางสถิติและไม่ครอบคลุมความเสี่ยงทั้งหมด แบบจำลองไม่รู้เงา ทิศหลังคา โหลดรายชั่วโมง ฤดูกาล การเสื่อมของแผง/แบตเตอรี่ ค่าเสียโอกาส เงินเฟ้อ การเปลี่ยนอินเวอร์เตอร์ ค่าธรรมเนียมกู้ หรือค่าซ่อมนอกแผน ระยะคืนทุนอาจเกินช่วงอายุอุปกรณ์ได้ จึงไม่ควรใช้เป็นคำแนะนำการลงทุนโดยลำพัง

บ้านที่มีโซลาร์อยู่แล้วใช้มิเตอร์ซื้อไฟแทนโหลดบ้านทั้งหมดไม่ได้ ควรใช้ข้อมูลอินเวอร์เตอร์/เครื่องวัดเพิ่มเติม มิเตอร์ต่อเนื่องควรใช้เลขเช้าของวันต่อไปตรงกับเลขเช้าถัดไปของวันก่อน หลีกเลี่ยงการนับวันซ้ำหรือเปลี่ยนมิเตอร์ระหว่างเก็บข้อมูล

## GitHub Pages — เตรียมไว้ ยังไม่เผยแพร่

อัปโหลด **เนื้อหาภายในโฟลเดอร์นี้** เป็นราก repository รวม `.github/`, `package-lock.json` และ `.gitignore` ไม่อัปโหลด `node_modules/` การ push ไม่ทำให้ workflow นี้เผยแพร่อัตโนมัติ

หลังเจ้าของโครงการอนุญาตเท่านั้น:

1. ตั้ง Settings → Pages → Source เป็น GitHub Actions
2. แนะนำตั้ง environment `github-pages` ให้มี required reviewer ถ้าบัญชีรองรับ
3. Actions → GitHub Pages (manual approval only) → Run workflow → กรอก `DEPLOY`
4. workflow จะติดตั้งจาก lockfile ทดสอบ สร้าง และเผยแพร่ dist

`base: './'` รองรับชื่อ repository ที่เปลี่ยนได้ แอปไม่มี path routing จึงไม่มี deep-link 404 เพิ่มเติม ขั้นตอนอ้างอิง [คู่มือ Vite สำหรับ GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages) ข้อความ DEPLOY เป็นตัวกันการกดพลาด ไม่ใช่ระบบยืนยันสิทธิผู้อนุมัติ ให้ใช้สิทธิ repository/environment ควบคู่กัน
